## 服务恢复与现场问题

45 个正式源码/ELF 中实际校验 45 个，SHA 全部保持一致；p275 未改，原 container ID 与可写层保留。9002 r152、8099 manager 和一份正常 watchdog 已恢复；实验进程、lease、完整进程 ENV、临时 RefuseManualStart/drop-in 和恢复 timer 已清理。正式入口 8k 回答一致性烟测见 production-http.json。

用户授权最多六小时，18:24:53 开始；重试没有重置计时。原保护截止 23:59:53，硬上限为次日 00:24:53。另在 23:59:20 提前 33 秒通过独立恢复 service 调度，保留原 timer/guardian，避免 controller 控制组超时打断其自身恢复命令。最终恢复发生在开始后 20440.2 秒；上限内恢复：True。测试检查点保留。

本轮开始前发现主机再次重启、同一 PCI 卡枚举回 3/5，原容器设备节点不匹配。已用停 dockerd、仅修正原容器节点的方式恢复。新增持久 fnx-boot-restore.service：按固定 PCI 对和原容器身份恢复原本在线的服务，尊重人工停止，拒绝替换活跃 Engine；健康服务复验不重启。它是保留的正常开机恢复能力，与已清理的实验 timer 不同。多次重启的原因仍未确认，不以时序推断是内核或优化造成。
