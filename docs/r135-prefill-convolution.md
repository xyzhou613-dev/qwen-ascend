# r135：长文 prefill 四点卷积融合

2026-11-10，2×910B4，262144 窗口，48 层 24+24，hybrid IPC，8192 主块。沿用 r125/r131/r132；新增 FNX_CONV_PREFILL=1。

原实现逐项生成四份 BF16 乘积，stack 后归约，在 8192 行时产生数百 MiB 中间张量。新 AscendC Vector 内核以 4096 token 为 tile，保留 BF16 乘积舍入、FP32 两两相加、最终 BF16 舍入，直接生成卷积结果。SiLU、历史更新及 DeltaNet 状态仍走原逻辑；128 行以下保留旧路径。

| 测例，服务器本机 HTTP | 本轮原基线 | r135 候选 | 改善 |
|---|---:|---:|---:|
| 8064 输入/128 输出，TTFT 中位数 | 5.298 s | 4.344 s | -18.0% |
| 同上，TPOT 中位数 | 45.42 ms | 43.16 ms | 输出速度 +5.2% |
| 262016 输入/128 输出，TTFT 单次 | 86.384 s | 73.602 s | -14.8% |
| 同上，TPOT | 46.81 ms | 44.46 ms | 输出速度 +5.3% |

每次使用新 nonce，8k 三次取中位数，256k 单次；无排队或并发模型。TTFT 为客户端首个文本增量；速度为 1000/TPOT。单次长文数值存在波动，生产复测另列；未宣称所有指标达到 20% 或硬件上限。

## 数值与算子验证

- 七组 D/T 形状，包含 65/124/129 不对齐 token 和 D=10240 的 128/512/2048/8192 行，每组八次动态输入，输出逐位一致。
- 真实 L00，decode 与四种 prefill 行数，每组八次动态输入，输出、FP32 递推状态和 BF16 卷积历史逐位一致。
- 8192 行卷积子图约 14.73→1.14 ms；完整层约 83.48→70.16 ms。子图测时用于归因，不能作为请求加速倍数。
- 完整候选 NLL=2.165267；15 个尾块、3 个策略切换边界、256k 三事实、重复缓存和追问全部通过。历史 100 题未重跑。

## 构建与回退

在容器可见的仓库副本中运行 `bash kernels/conv_prefill/build.sh`，输出 `fnx/libfnx_conv_prefill.so`，目标 dav-c220-vec/CANN 9.1.0。与 `fnx/conv_prefill.py` 一起部署；也可用 FNX_CONV_PREFILL_SO 指定库。Git 只保存源码，二进制校验值见 benchmarks/r135/binary-manifest.json。

框架默认关闭，生产脚本显式启用。设置 FNX_CONV_PREFILL=0 并重启可单独回退；FNX_RAW_COMPACT=0、FNX_PIPELINE_SHORT_CHUNK=0、FNX_CPU_THREADS=1 分别关闭其他本轮优化。候选启动约 249 秒，更多分块图仍有额外捕获成本。

## 本轮后续被否决

卷积后改为 token-major 或仅压紧 q/k 的布局没有明显整层收益；Raw 投影二合一/四合一未得到稳定收益且改变末位数值，均未进入生产源代码。
