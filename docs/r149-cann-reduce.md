# r149 保留 CANN 归约：精度通过，整模型无稳定收益

本轮在 r144 基础上，将 q/k 的 BF16 平方合并，继续使用 CANN ReduceSum，再融合后处理；测试 split / joint 两种形状，整模型使用 joint。没有改变正式部署。双卡各512组组件输入、4个历史稀疏反例、65536种BF16编码的query缩放均逐位一致；36个真实权重DeltaNet子路径共864例，输出、卷积历史和FP32状态逐位一致。完整L00/L12/L24/L44 decode及128/512/2048 prefill也通过。

| 场景 | r144 TPOT ms | 候选 TPOT ms | 输出速度变化 |
|---|---:|---:|---:|
| fresh 8k（三次中位） | 33.69 | 33.65 | +0.119% |
| fresh 256k（各一次） | 34.36 | 34.42 | -0.174% |
| 缓存256k（各一次、非流式） | 33.98 | 34.07 | -0.264% |

8k固定8064输入+128输出；256k固定262016输入+128输出，三事实召回3/3。基线与候选各重启，使用相同配置、权重与冻结请求，在仅本机19002端口测量。三份8k完整回答及256k回答相同；6k/12k/24k的597个目标NLL与argmax全部逐位相同。256k TTFT约69.93→69.92s，无可确认收益。

组件事件时间约16.7→10.1–10.2µs没有转化为稳定整模型加速：8k仅+0.119%，256k反降0.174%，未达预设两场景均>0.5%的门禁。候选被否决，未安装；测试结束恢复r144及管理器。不能将组件收益算作已交付加速。

另用四个稀疏反例定位 r148 全融合的累加顺序问题：平方逐位一致，但原128元素原生归约与CANN不同。先逐元素相加两个64元素片段，再对64元素归约，四例都与CANN一致。该实证仅针对本机固定R=128路径，不宣称所有CANN归约都如此；r150据此继续扩大测试。

证据不含完整进程ENV、权重或用户激活；sum-trace-device*.json与norm_pair.cpp保存两种归约顺序对拍，旧r148的四个合成反例可复用。历史线上组件计时在非独占条件下完成，整模型A/B为受控独占。正式服务在r150维护前仍为r144。
