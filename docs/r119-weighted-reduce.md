# r117–119 通道混合与 MoE 加权归约优化

2026-11-05；2×Ascend 910B4；48 层 24+24；256k；8192-token 主块；hybrid IPC；W4 专家、BF16 KV、FP32 DeltaNet。基线提交 1fa72591。本轮未改变路由、Top-K、量化或递推精度。

每层两次通道混合原为 BF16 逐元素乘法与均值归约，改成同一个 AscendC 内核。MoE 则融合专家输出逆序 Gather、BF16 权重相乘和归约；decode 支持专家输出的行跨度。预填仅在至少 512 行的逆序索引分支启用专家融合，小块保留原 scatter 路径。共享专家相加、Sigmoid、RMSNorm、路由及专家矩阵乘保持原路径。

子图计时为独占设备上图回放并同步的墙钟时间；B=1 每图含 32 次调用，其余每图一次、取多次中位数，不能直接当作请求收益。最终判断采用上面的完整请求数据。

- 保留每项 BF16 乘积舍入，再按原 CANN 路径以 FP32 顺序累加，通道混合最后乘 1/4 并回 BF16。消减误差用例验证不能改成树形归约。
- 两类子图均检查 1/128/512/8192 行以及图内动态输入与权重，输出逐位一致。真实 L00 完整前向检查 128 步动态 decode 和 128/512/8192-token 分块，输出、BF16 卷积历史与 FP32 递推状态均逐位一致。
- 基线、候选及生产复测的 200-token NLL 均为 2.165267，冻结参考为 2.164792±0.01；三处资料检索 3/3，重复请求新增 prefill 为 0，追问新增 prefill 29 token 并正确回答 7319；候选持续生成达到 1024 token。
- 历史 100 题没有在本轮重跑。局部逐位对照和 NLL 是回归检查，不扩展为新的通用能力结论。

## 实现经验

首版逐组搬运和同步虽精度通过，但 8192 行时通道混合 0.731→1.880 ms、专家加权 2.181→3.961 ms，因此未启用。第二版提前批量搬入一行全部组，预填使用完整 2560 列，decode 使用 128 列铺开核心，才得到上面的完整请求结果。早期原型缺少 Cast→Muls 的 Vector 屏障，已在独立测试中发现并补齐；该原型从未进入服务路径。

## 构建、开关与回退

执行 kernels/reduce/build.sh，目标 dav-c220-vec。将生成的 libfnx_reduce.so 与 fnx/weighted_reduce.py 放在同一目录，或设置 FNX_WEIGHTED_REDUCE_SO。共享库现场编译，Git 只保存源代码。

FNX_MIX_REDUCE=1 与 FNX_MOE_REDUCE=1 启用两处融合，默认关闭；生产脚本已启用。模型宽度、dtype 和布局不满足支持条件时保留原路径。关闭对应开关并重启可单独回退；本机整轮回滚为 bash /root/ascend-dev/r119/rollback.sh。

该轮请求样本用于确认当前机器上的收益，没有声称已达到硬件上限。下一轮仍可定位 FP32 DeltaNet 分块准备与稀疏注意力的设备时间。
