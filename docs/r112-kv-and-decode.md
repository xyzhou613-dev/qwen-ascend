# Flash Next 双 KV 写入融合与解码同步优化

2026-11-05，同一台双 910B4、48 层 24+24、256k、8192-token 主块、hybrid IPC。

双 KV 写入合并原始 K/V、packed latent 与 RoPE 四个目的缓冲区的写入。对齐输入按块搬运，保持 BF16 位型和缓存布局。8192-token 子图在独占卡上从 1.531 ms 降至 0.290 ms。精度覆盖非连续源、六种长度和动态位置重放。

父进程 prefill 使用已经维护的主机位置，发布 IPC 前同步。worker 有输出时由标量读取等待本流，无输出仍显式同步。跨进程传输继续使用双缓冲与有序发布。

DeltaNet 装载时预计算固定衰减权重。紧凑路径把 BF16 到 FP32 的展开移入 AscendC，复用三个 value head 共享的 query/key。真实 L00 的 256 步动态回放，FP32 状态、BF16 卷积和输出均逐位一致。单层子图时长基本持平，速度以整请求为准。

在大块 prefill 中融合索引四头 ReLU 与顺序 FP32 归约，保留原来的标量除法、因果掩码与 Top-K。512 行 × 65536 组子图的评分和选中组逐位一致，耗时 3.21→2.28 ms。仅在分组数达到 16384、tile 至少 128 行、布局符合要求时启用。

除持续生成外，均使用全新 262016 输入和 128 输出。持续生成使用 261120 输入和 1024 输出。三事实检索 3/3，原文重复无新增 prefill，追问通过。生产两次 200-token NLL 均在冻结门限内。
样本包括同机基线一次、候选和生产各一次 128-token 长请求，1024-token 持续生成作为独立长度测例。百分比依据相同输入输出长度的基线与生产复测。

在生产 CANN 环境执行 `bash kernels/dual_write/build.sh`。若启用紧凑 DeltaNet，需重新执行 `bash kernels/delta_native/build.sh`。生成的共享库与 Python 模块须部署在同一运行目录。关闭 `FNX_DUAL_WRITE` 或 `FNX_DN_COMPACT` 并重启可分别回退内核路径。

索引归约共享库使用 `bash kernels/score/build.sh` 构建。关闭 `FNX_INDEX_SCORE` 并重启可单独回退该路径。
