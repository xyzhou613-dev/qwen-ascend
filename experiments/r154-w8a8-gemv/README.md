# Experimental r154 candidate (not deployed)

Production remains r152. Read docs/r154-w8a8-gemv.md and the negative results.
Do not apply the initial ordinary-W8A8 engine.patch as the selected candidate:
ordinary and output-BF16 variants failed the development NLL slice gate.

The selected package consists of selected-engine.patch and fnx/w8a8.py plus
fnx/smooth_w8a8.py. It is disabled unless FNX_DENSE_W8A8=1. Enabling it requires
FNX_W8A8_CALIB_DIR pointing to frozen, reviewed L00..L47.safetensors activation
maxima generated by calibrate.py; these files contain calibration statistics,
not model weights, and are intentionally retained privately on the server.
Defaults do not change production. No production installer/startup toggle was run.

Selected constructor wiring was bitwise checked against the validated manual
SmoothQuant implementation on four real layers, four steps each. The 2048-target
development NLL gate passed after fixed-alpha calibration, but independent task,
long-context/prefill quality and candidate HTTP A/B acceptance remain outstanding.

The direct INT4 gate/up kernel is slower and was rejected. The down kernel is
faster as a component, but uses a different weight layout. Its phase converter
has substantial request overhead, and full model phase/cache/graph lifecycle
is not implemented. Do not enable it merely because an ELF is provided.

ELFs target Linux aarch64 Ascend 910B/CANN9.1, not Windows. Source and explicit
output build paths are provided for reproduction in an isolated directory.
