# r131：按请求长度选择流水分块与 CPU 嵌入并行化

2026-11-10，2×910B4，256k 窗口；基于 71daa94/r125 分块配置。保留权重、路由、BF16 KV 与 FP32 递推精度。

## 请求实测

服务器本机 HTTP，全新输入：8k=8064 token、256k=262016 token，均输出 128 token。8k 各三次取中位数，256k 各一次；不同 nonce 避免命中缓存。

| 测例 | 原配置 | r131 完整候选 | 变化 |
|---|---:|---:|---:|
| 8k TTFT | 5.298 s | 4.651 s | -12.2% |
| 8k TPOT | 45.42 ms | 46.01 ms | +1.3%，输出未提速 |
| 256k TTFT | 86.384 s | 81.839 s | -5.3%，单次样本 |
| 256k TPOT | 46.81 ms | 47.24 ms | +0.9%，输出未提速 |

配置分解：仅中等图 8k TTFT=4.949 s；再用 CPU 16 线程=4.887 s；同一进程将流水上限设为 2048 后=4.639 s。最后的自动策略重新启动完整服务得出表中 4.651 s。不能把逐步结果相加或将 CPU 子步骤的倍数当作整机倍数。

CPU 嵌入默认 1 线程，8192 行反量化微基准约 100.3→9.4 ms，40 组 1/128/512/4096/8192 行 BF16 逐位一致。生产脚本用 OMP_NUM_THREADS/MKL_NUM_THREADS=16；可用 FNX_CPU_THREADS=1 回退。

PipelineModel.plan_prefill 根据本次未缓存 token 数选择上限：≤16384 用 2048，其余保留 8192；仍先执行原来的前 2048 token 的 512 行块。保留缓存命中、位置和跨卡双缓冲流程。FNX_PIPELINE_SHORT_CHUNK=0 可关闭策略；框架默认关闭，生产脚本启用。

## 验收

NLL=2.165267，冻结参考 2.164792±0.01；15 个尾块边界、策略切换点 n_prefill=16383/16384/16385 全通过；256k 三处事实 3/3、重复请求新增 prefill=0、追问新增 29 token 并回答 7319。CPU HTTP 回归 25/25。历史 100 题本轮未重跑。原始证据见 benchmarks/r131。

新增图增加装载后的捕获时间，本轮完整候选启动约 4.5 分钟；这是首 token 改善的启动成本。该候选通过隔离验收，生产切换待本轮布局候选收敛后统一进行。没有宣称达到 20% 或硬件上限。

## 本轮被否决的方向

- 新增极小尾图与 worker 早期短块图：精度检查通过，完整请求无明显收益。
- MoE selected/full GMM：完整子图比现路径慢，且有 BF16 末位差异，不启用。
- 融合 gate/up 权重及 scale 搬运：32 组动态路由逐位一致，但完整 MoE 子图仅约 0.7% 收益，未作为生产新算子引入。
- DeltaNet 每块四个 FP32 BMM 合为两个：80 组子图、24 组真实 L00 分块输出/状态逐位一致，但 2048 行函数 7.84→8.56 ms、完整层 26.43→27.16 ms，未启用。

## 最新设备 trace

采样基于当前 r119 算子和 r120/71daa94 服务，四种旧分块、CPU 1 线程；采样刻意排空两级流水，关闭对话快照，只用于归因，不替代 HTTP 性能。decode 每阶段各取 16 token，采样 8k 与 256k 历史；另取 8k prefill 和 256k 晚期两个 8192 行块。

256k decode 两阶段 kernel 时长累计约 44.87 ms/token：普通 MatMul 13.66 ms、WQBM 4.02 ms、GMM 4.27 ms、Gather 3.35 ms。矩阵乘配套转置/裁剪累计约 5.6 ms/token。合计并非各项可直接省下的端到端时间。优先检查小矩阵投影的权重跨度与布局；长文则需同时看 SparseFlashAttention、FP32 DeltaNet、小算子准备和 MoE，而非仅减少 BMM 次数。
